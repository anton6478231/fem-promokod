# ФЭМ сайта промокодов

Локальный дашборд: забрать сайт промокодов у подрядчика. Две вкладки с одной формулой.

**Онлайн:** https://anton6478231.github.io/fem-promokod/

## Запуск

```bash
cd "/Users/anton/Desktop/mini CEO/финмодель-сайт-промокодов"
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

Откроется `http://localhost:8501`

## Вкладки

| Вкладка | Что считает |
|---|---|
| **Base** | N месяцев разработки, дальше только поддержка. Органический трафик как сейчас, без зарплат, без рекламы, без лифтов. Ответ на вопрос: отобьётся ли забор сайта на текущем потоке. |
| **Stretch** | То же + ручной продуктовый RnD (ЗП и лифты после завершения) + реклама с отдельной воронкой активации. |
| **Параметры** | Полная вбивка по сценариям (вкладки Base / Stretch внутри). Коэффициенты не сбрасываются при переключении. |
| **Логика модели** | Формулы |

Горизонт расчёта общий. Остальные коэффициенты живут раздельно: `base__*` и `stretch__*` в session_state. На Stretch есть кнопка «Скопировать органику из Base».

## Формула

```
Промо канала = трафик_канала × CR_канала × доля_одобренных_канала × доля_оплачиваемых_канала × ARPU
Выручка      = промо_органика + промо_реклама + карты + доп. выручка RnD
```

Рекламный и органический трафик **нельзя** смешивать в один CR: холодный трафик конвертируется иначе, и Base сразу перестанет отвечать на вопрос про окупаемость органики.

После переезда на свой сайт органика умножается на SEO-фактор: в первый месяц своего сайта — пол (база 70%), к N-му месяцу своего сайта линейно 100%. Реклама и статус-кво не проседают. Пол и срок задаются отдельно в Base и Stretch.
